# Plan 07-01: Backend Test Suite Consolidation

## Objective
Establish a standard, cross-platform `npm test` script in `server/package.json` that executes the existing test suites (`test-signaling.js`, `test-reports.js`, `test-history.js`, `test-integration.js`) with deterministic exit codes and clear summary outputs suitable for CI and local development.

## Context
- `server/` contains 4 integration test scripts: `test-signaling.js`, `test-reports.js`, `test-history.js`, `test-integration.js`.
- Currently, tests are only executed together on Windows via `run-tests.bat`, which cannot run on Linux/macOS or in GitHub Actions without PowerShell/CMD.
- `server/package.json` lacks a `"test"` script.

## Tasks
1. **Create Test Runner Script (`server/test-runner.js`):**
   - Implement an ESM test runner script that runs all test suites sequentially.
   - Capture stdout/stderr and track pass/fail exit status per test module.
   - Exit with code 0 if all tests pass; exit with code 1 if any test fails.
   - Support running individual test suites via CLI argument (e.g. `node test-runner.js signaling`).
2. **Update `server/package.json`:**
   - Add `"test": "node test-runner.js"` under `"scripts"`.
   - Add `"test:signaling": "node test-signaling.js"`.
   - Add `"test:reports": "node test-reports.js"`.
   - Add `"test:history": "node test-history.js"`.
   - Add `"test:integration": "node test-integration.js"`.
3. **Verify Local Execution:**
   - Execute `npm test` in `server/` to ensure the runner works on Windows and reports structured results.

## Verification Criteria
- [ ] Running `npm test` inside `server/` executes the test suites and reports status.
- [ ] Exits with code 0 on success and non-zero on failure.
- [ ] Cross-platform compatibility (works identically in bash, powershell, and cmd).
